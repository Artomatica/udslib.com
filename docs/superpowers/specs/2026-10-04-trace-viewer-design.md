# UDS trace analyzer + visual viewer (uds-toolbox v1.1)

Approved scope 2026-10-04. Value proposition: **"Drop a CAN trace and get told why your diagnostic session or flash failed."**

## Deliverables

1. Pure ESM analysis library `mcp-worker/src/trace/` (no Node APIs, no deps; runs in Cloudflare Worker AND browser):
   - `parse.mjs`: `parseTrace(text, {format?}) -> { format, frames: [{ i, t /*ms float*/, id /*number*/, ext /*bool*/, dir /*'rx'|'tx'|undefined*/, data /*number[]*/ , fd /*bool*/ }], warnings: string[] }`. Auto-detect format when not given. Formats:
     - `candump`: `candump -L` log lines `(1696412345.123456) can0 7E0#0210030000000000` and also plain candump `  can0  7E0   [8]  02 10 03 00 00 00 00 00` (the existing `decodeIsotp` already parses both: reuse/extract that parser, don't duplicate). CAN FD `##` form: `7E0##1<hex>`.
     - `asc` (Vector ASCII): header lines `date ...`, `base hex  timestamps absolute`, `internal events logged`, `Begin Triggerblock`; data lines `   0.012345 1  7E0             Tx   d 8 02 10 03 00 00 00 00 00` (channel, id with optional trailing `x` for extended, Rx/Tx, `d`, DLC, bytes; may have trailing `Length = ... BitCount = ...` fields — ignore them). `base dec` means IDs in decimal. Also CAN FD lines `CANFD   1 Rx  7E8  ...  1 0 8 8 <bytes>`: support the common form `<t> CANFD <ch> <Rx|Tx> <id> <symbolic?> <brs> <esi> <dlc> <len> <bytes...>` best-effort; skip lines you can't parse with a warning. Skip `ErrorFrame`, `Statistic`, comments `//`.
     - `trc` (PEAK PCAN-View): versions 1.1 (`;$FILEVERSION=1.1`, lines `    1)      1234.5  Rx         07E0  8  02 10 03 00 00 00 00 00`), 2.0 and 2.1 (`;$FILEVERSION=2.1`, `;$COLUMNS=N,O,T,B,I,d,R,L,D`, lines `      1      1059.900 DT 1      07E0 Rx -  8    02 10 03 00 00 00 00 00`). Use `$COLUMNS` when present. Time column is ms offset.
     - `csv`: SavvyCAN/GVRET header `Time Stamp,ID,Extended,Dir,Bus,LEN,D1,D2,...,D8` (timestamp in microseconds, ID hex) and python-can header `timestamp,arbitration_id,extended,remote,error,dlc,data` (timestamp seconds, id decimal or hex, data hex string). Detect by header.
   - `analyze.mjs`: `analyzeTrace(frames, opts?) -> Analysis` doing:
     - ISO-TP reassembly per CAN ID (reuse `isotp.mjs` logic; factor shared code rather than copy). Detect tester/ECU pairs automatically: requests go tester→ECU, responses ECU→tester; physical pairs like 7E0/7E8, 18DA F1xx; also functional 7DF. Heuristic: a message whose first byte is a valid request SID followed within 5 s by a response (SID+0x40 or 7F SID) on another ID forms a pair.
     - Request/response pairing with `0x78 responsePending` handling (pending responses attach to the request; final response ends it). Per pair: `{ n, reqT, rspT, latencyMs, service, sid, sub, request: hex, response: hex, positive, nrc?, pendingCount, frameRefs:[i...] }`.
     - Timing: P2 = request→first response latency; P2* = between pending and final. Stats {count, p50, p95, max}. Flag pairs with no response within 5000 ms (`timeout`).
     - Timeline events: session changes (0x10 + response with P2/P2* values), security (0x27 seed/key, NRC 0x35 invalidKey, 0x36 exceedNumberOfAttempts, 0x37 requiredTimeDelayNotExpired → `lockout` finding), routines (0x31 with RID name), DTC ops, communication/DTC setting, ECU reset, tester present (summarize, don't list each).
     - Flash: 0x34 RequestDownload (address/size from ALFID) → 0x36 blocks (counter sequence check incl. wraparound 0xFF→0x00, bytes, duplicates/retries) → 0x37. Output `{ address, size, bytesTransferred, blocks, maxBlockLength, durationMs, throughputBps, complete, gaps:[...], crc32 /* of reassembled image */, counterErrors }`. Image reconstruction: concatenate 0x36 payloads in counter order (dedupe retransmits of the same counter), crc32 (IEEE) of the result; expose `imageBase64` only from the browser API, not in the MCP structured output.
     - Identification: VIN (F190), F18C serial, F187/F195 etc. from 0x62 responses (ascii when printable).
     - Findings: `[{ severity: 'error'|'warning'|'info', code, title, detail, frameRefs:[i], pairRef? }]` and `rootCause`: the first error-severity finding in time order that explains the failure (e.g. "Flash aborted: TransferData block 0x12 answered 7F 36 73 wrongBlockSequenceCounter after a retransmit", "Security locked: 3 invalid keys (0x35) then 0x36 exceedNumberOfAttempts", "ECU stopped responding after 0x31 eraseMemory (no response in 5 s)", "Programming session refused: 7F 10 22 conditionsNotCorrect"). `null` when no error.
     - Summary: `{ format, frames, durationMs, canIds, isotpMessages, pairs, positive, negative, timeouts, ecus:[{tester, ecu}] }`.
   - Must handle 100k frames in < 2 s in Node.

2. MCP tool `analyze_trace` in `tools.mjs` (+ tests):
   - input `{ trace?: string, file?: { download_url, file_id, file_name?, mime_type? }, format?: 'auto'|'candump'|'asc'|'trc'|'csv' }`. One of trace/file required. File: `fetch(download_url)`, reject > 10 MB, text decode UTF-8 (BLF/pcap/MF4 → clear "not supported yet; export as ASC or candump" error).
   - tool `_meta`: `"openai/fileParams": ["file"]`, `"openai/outputTemplate": "ui://widget/trace-viewer.html"`, `"openai/toolInvocation/invoking": "Analyzing trace…"`, `"openai/toolInvocation/invoked": "Trace analyzed"`, `"openai/widgetAccessible": true`. Annotations read-only/closed-world/non-destructive like the others (openWorldHint stays false; fetching the user's own uploaded file is not open-world). Title "Analyze CAN trace".
   - result: text = root cause + short summary (≤ 40 lines); `structuredContent` = Analysis trimmed: pairs ≤ 400 (keep all negatives + first/last), timeline ≤ 300, findings all, flash without image; plus `truncated: bool`.
   - `tools/list` must include `_meta` for this tool (currently mcp.mjs strips fields; pass `_meta` through).
3. MCP resources: `initialize` advertises `capabilities.resources`; `resources/list` returns the widget; `resources/read` for `ui://widget/trace-viewer.html` returns `{ contents:[{ uri, mimeType:"text/html+skybridge", text: <html>, _meta: { "openai/widgetCSP": { connect_domains: [], resource_domains: [] }, "openai/widgetDescription": "Timeline of a UDS diagnostic session from a CAN trace", "openai/widgetPrefersBorder": true } }] }`. HTML is a build artifact imported as a string module (`src/generated/widget-html.mjs`, generated by the build script, committed).
4. Viewer UI (`viewer/`): vanilla JS + CSS, no framework, no external requests.
   - `viewer/render.mjs`: `renderAnalysis(container, analysis)` — header summary chips; **root-cause card** (red) with "show frames" link; **timeline** (SVG, horizontal time axis, lanes: Session, Security, Flash, Routines/Other; each pair a mark, NRC red, 0x78 amber, timeouts hatched; hover tooltip; click selects); **flash panel** (progress bar bytes/size, throughput, block counter errors, CRC32, gaps); **pairs table** (time, latency, service, request hex, response hex, NRC name), filter: all/negative/flash/security; **detail pane** for the selected pair showing the full `decodeUds` output of request and response and its raw frames.
   - Light/dark via `prefers-color-scheme`; fits 360 px width (table scrolls inside container).
   - `viewer/widget-entry.mjs`: reads `window.openai.toolOutput` (structuredContent) and re-renders on `openai:set_globals` events; requests fullscreen via `window.openai.requestDisplayMode?.({mode:'fullscreen'})` from a button.
   - `viewer/page-entry.mjs`: for `udslib.com/viewer.html`: drop zone + file picker + paste box + "load example" button; parses **locally** with `parseTrace`+`analyzeTrace`; "Download reconstructed image (.bin)" button when flash data exists. States clearly "Parsed in your browser. Your trace never leaves this page."
   - Build: `mcp-worker/scripts/build-viewer.mjs` using **esbuild** (devDependency only) to bundle (a) widget: single self-contained HTML (inline JS+CSS) → `mcp-worker/src/generated/widget-html.mjs` (export default string), and (b) page bundle → repo-root `viewer/app.js` + `viewer/app.css`; repo-root `viewer.html` (site template header/footer like `pricing.html`, GA tag, nav gets a "Trace viewer" link on all pages). `npm run build` runs it; CI-less, so commit generated files.
5. Examples: `mcp-worker/test/fixtures/` generated by `mcp-worker/scripts/make-fixtures.mjs` from ONE scripted scenario rendered into all four formats (candump -L, asc, trc 2.1, savvycan csv) + `trc 1.1` + python-can csv variants. Scenario (tester 7E0 → ECU 7E8, 1 ms frame spacing realistic): 10 03 → 50 03 …; 22 F190 → VIN multi-frame; 85 02; 28 03 01; 10 02; 27 01 seed; 27 02 bad key → 7F 27 35; 27 01; 27 02 good → 67 02; 31 01 FF00 → 7F 31 78 → 71 01 FF 00; 34 00 44 08000000 00000400 → 74 20 01 02; 36 01..04 (256 B each, multi-frame ISO-TP with flow control) → 76 xx, with block 03 retransmitted once; 37 → 77; 31 01 FF01 → 71 01 FF 01 00; 11 01 → 51 01. Plus a second scenario "failed flash": block counter skip → 7F 36 73 and an ECU timeout after 31 01 FF00. Copy the success example to repo-root `viewer/examples/flash-ok.asc` and failure to `viewer/examples/flash-fail.trc` for the page's "load example".

## Tests (node --test, must all pass; keep the existing 88)

- Every fixture format parses to the same frame list (ids, data, relative times within 0.01 ms).
- Success scenario: 0 errors, rootCause null, flash.complete true, bytesTransferred 1024, crc32 equals crc32 of the generated image, retransmit counted once, VIN extracted, security finding `invalidKey` warning then unlocked, P2* recorded for the 0x78.
- Failure scenario: rootCause code `wrongBlockSequenceCounter` (first error), plus `timeout` finding; frameRefs point at the right frame indexes.
- ASC with `base dec`, extended IDs `18DAF110x`, and junk lines → warnings, no throw.
- analyze_trace via MCP: text path, file path (stub `fetch` with a local server or monkeypatched global fetch), >10 MB rejected, binary (BLF magic `LOGG`) rejected with the export hint.
- `resources/read` returns html containing `renderAnalysis` and mimeType `text/html+skybridge`; `tools/list` includes `openai/outputTemplate` for analyze_trace only.
- Perf: 100k synthetic frames analyzed < 2 s.
